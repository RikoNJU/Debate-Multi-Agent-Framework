# 评分稳定性与论文修订识别

## 状态

已实现并由自动化测试验证。该机制用于缓解同一论文重复评审时的随机波动，不能保证不同模型版本或人工规则版本之间分数完全一致。

## 设计结论

旧项目稳定性的核心不是简单将温度设为 0，而是先按章节执行固定评审小项，再把有限等级判断映射到评分档位，最后使用确定性公式汇总。本项目保留多智能体发现问题和 Chair 核验证据的能力，同时引入同类约束。

### 固定章节评审小项

- 评审小项按章节阶段、专家角色和 12 个语义评分维度版本化管理。
- 三位专家必须逐项输出 `excellent/good/acceptable/poor/critical`，成功任务不允许缺项。
- `poor` 和 `critical` 必须关联带论文证据的 Finding；漏项或负面判断无证据会拒绝该专家输出并自动重试。
- Chair 必须对每个初审 Finding 给出 `confirmed/rejected` 二元裁决；证据不足按负面结论的举证责任判为 `rejected`。
- Chair 驳回关联 Finding 后，负面小项按“无已证实缺陷”回落为 `acceptable`，不再存在伪人工兜底状态。

### 稳定评分

- 有效小项等级先映射为固定锚点分，再聚合到 12 个语义维度。
- Step 7 大模型仍输出候选分，用于保留少量语义差异，但最终分数被限制在锚点正负 1 分以及原有等级区间内。
- 5 项格式结构分、1 项参考文献分和 12 项语义分仍使用原项目迁移来的确定性公式汇总。
- 结果同时保存模型原始候选分、锚点分、最终分、rubric 版本和 scoring rule，便于审计评分波动来源。

## 同稿复用规则

评审指纹包含：

- 规范化论文正文 SHA-256；
- 用户指定的论文类型或 `auto` 模式；
- 模型名称；
- Pipeline 版本；
- 固定评审小项版本；
- 评分规则版本。

仅当指纹完全一致且历史任务成功完成时，系统才复用结果。同一 PDF 重复上传会在 MinerU 前命中已有任务；不同 PDF 但规范化正文一致时会保留新修订记录并复制已验证结果。

## 小幅修改识别

- 每个修订保存原始 PDF 哈希、规范化正文哈希、章节哈希和父修订 ID。
- 未显式提供 `paper_id` 时，系统只在标题相同的当前修订中比较正文。
- 正文使用位置无关的字符 shingles 计算 Dice 相似度；相似度不低于 0.97 时归入同一论文。
- 任何正文内容变化都会产生新的评审指纹并执行完整评审，即使只修改一句话。
- API 返回 `revision_id`、`change_ratio`、`changed_chapter_ids` 和 `reused`，前端可用于展示修订状态。

## 数据库变更

迁移 `20260824_0006` 为论文修订增加正文哈希、父修订、章节哈希和变化摘要，为评审任务增加可检索的评审指纹。SQLite 旧库由应用层维护父修订关系；新建数据库及支持在线添加约束的数据库使用自引用外键。

## 当前边界

- 尚未实现“只重评发生变化的章节”。小改论文仍完整评审，这是为了避免章节间影响和缓存污染。
- 0.97 阈值目前是保守工程值，需要用真实论文修订对构建评估集后再校准。
- 当前测试证明规则和数据流可重复，不等于已经用真实模型完成大规模评分方差评测。
- 模型温度不是唯一稳定性手段。专家为 0.1、Chair 为 0.05、摘要为 0.2、评分为 0.1，允许语言表达存在变化，而结构判断和最终分数受规则约束。

## 验证用例

- 漏答固定小项时拒绝专家输出并触发重试，无法补全则任务失败。
- 无 Finding 证据的负面判断拒绝专家输出；Chair 驳回的问题不会继续扣分。
- 任一 Specialist 最终失败时不生成不完整评分。
- 极端不同的模型候选分在同一锚点下最终相差不超过 2 分，且不跨旧评分档位。
- 长文本只插入一句时仍识别为同一论文的新修订，但评审指纹发生变化。
- 仅空白和排版变化时规范化正文哈希一致，可复用结果。
- 相同 PDF 第二次上传跳过 MinerU 并返回原成功任务。
